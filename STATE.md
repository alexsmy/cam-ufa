## Что это

Статическая страница с превью 72 камер строек и ЖК Уфы. Каждые 10 минут GitHub Actions
скачивает по одному кадру с каждой камеры, собирает страницу и публикует её через GitHub Pages.
Превью и архив кадров в git не хранятся — они попадают только в публикацию.

## Файлы

| Файл | Назначение |
|---|---|
| `cams.json` | список камер: `id`, `jk` (ЖК), `title` (подпись). Единственный источник данных |
| `template.html` | вёрстка страницы с плейсхолдерами `{{SECTIONS}}`, `{{STAMP}}` и т.д. |
| `refresh.py` | скачивание кадров, сборка `index.html`, архив, чистка старого |
| `watch.html` | свой просмотрщик камеры: зум кнопками и пальцами, панорамирование |
| `icon.svg`, `og.png` | иконка сайта и картинка-превью для мессенджеров |
| `.github/workflows/update.yml` | расписание, публикация, keepalive, лог |
| `requirements.txt` | `imageio-ffmpeg` (ffmpeg без установки) |
| `index.html` | снимок страницы для отката; обычно пересобирается `refresh.py` |
| `README.local.md` | локальная памятка, в git не попадает (в `.gitignore`) |

## Как работает публикация

1. Триггеры: `push` в `main` (публикует сразу), ручной Run workflow и **самоподдержка**.
   GitHub-cron ненадёжен, поэтому после каждого деплоя job `chain` запускает `ticker.yml`,
   тот ждёт 6 минут и запускает `update.yml` заново — итого цикл ~10 минут.
   Резервное расписание `schedule` (`13 * * * *`) оставлено на случай обрыва цепочки.
2. `refresh.py` в 4 потока скачивает кадры, кодирует в WebP 480 px, повторяет при ошибке.
3. `previews/<id>.webp` — текущие превью; в HTML подключаются как `?v=ГГГГММДДЧЧММ`.
   Метка меняется каждые 10 минут → браузер не держит старую картинку дольше десяти минут.
4. `archive/<id>/<ГГГГММДДЧЧММ>.webp` — кадр на каждый запуск, хранится 24 часа,
   старые удаляются при каждом запуске (до 144 кадров на камеру). В git архив не лежит:
   перед сборкой workflow скачивает предыдущую публикацию Pages и восстанавливает
   `archive/` из неё, иначе на чистой виртуалке архив каждый раз начинался бы с нуля.
5. `archive/index.json` — список кадров для окна таймлапса (⏱ в карточке).
   Старые кадры с шагом 24–30 минут записываются в него по 2–3 раза, чтобы при
   16 кадрах/с таймлайн не прыгал; новые 10-минутные идут по одному. Файлы не
   копируются: повторы исчезают сами, когда старые кадры выходят из 24-часового окна.
6. Папка `_site` → `upload-pages-artifact` → `deploy-pages`. Коммитов с превью больше нет.

## Что уже сделано

- **P0.** Переход на публикацию через GitHub Actions (история репозитория больше не растёт),
  UTF-8 в `refresh.py` (работает на Windows), вычищены дубли мета-тегов и `?t=`-редирект,
  кэш превью 10 минут.
- **P1.** Данные вынесены в `cams.json`, поиск по ЖК, ★ избранное (запоминается в браузере),
  бейдж «нет сигнала», счётчик «онлайн N», «обновлено N мин назад», автообновление страницы
  через 11 минут с сохранением позиции, кнопка «наверх».
- **P2.** WebP 480 px вместо 320 JPEG, тёмная тема (по системной), сетка 1–4 колонки,
  `alt`-тексты, иконка сайта, OG-превью для Telegram.
- **Мобильное.** Круглая кнопка `1`/`2` в шапке (показывает текущий режим, по умолчанию 2),
  компактная шапка, отступы 14 px в шапке и 10 px у контента.
- **Кнопка ⟳ убрана.** Она лишь перезагружала вкладку и выглядела как «обновить камеры».
- **Таймлапс.** Кнопка ⏱ в карточке — светлая градиентная, заметная; кадры за сутки,
  ползунок, ▶/⏸, выпадающий список скорости 4–16 кадров/с (по умолчанию 16).
  При открытии окна воспроизведение стартует автоматически с самого старого кадра,
  доходит до самого свежего и останавливается (один проход, без повтора).
  Кнопка «Скачать MP4» даёт готовый ролик H.264 (480×270, 16 кадров/с), который
  `refresh.py` собирает ffmpeg'ом из всех кадров камеры. Все кадры архива приводятся
  к ширине 480 px: старые кадры меньшего размера при необходимости увеличиваются.
  Старые кадры с шагом 24–30 минут повторяются 2–3 раза при воспроизведении и экспорте,
  пока не выйдут из суточного архива; новые 10-минутные идут по одному.
  Список готовых роликов — `archive/videos.json`; GIF и `gifenc.esm.js` убраны.
- **Просмотрщик.** `watch.html`: тонкая тёмная полоса сверху (назад, название камеры,
  лупа масштаба, «оригинал»). В обычном режиме над плеером Уфанета нет ничего —
  все касания идут в плеер. Кнопка лупы включает режим приближения ×2/×3/×4:
  в нём работают пинч двумя пальцами и сдвиг одним, двойное касание сбрасывает
  масштаб. Кнопки никогда не перекрывают видео.
- **Возврат к списку.** Позиция прокрутки сохраняется при каждом движении и
  восстанавливается после возврата с камеры и после авто-обновления страницы.
- **Инфраструктура.** keepalive-коммит раз в неделю (иначе GitHub отключает расписание
  через 60 дней без активности), отчёт в лог запуска, ретраи, удаление превью мёртвых камер.

## Как продолжить на другом компьютере

```bash
git clone https://github.com/alexsmy/cam-ufa.git
cd cam-ufa
git checkout improve/v2
python -m pip install -r requirements.txt
python refresh.py                 # скачать кадры и собрать index.html
python refresh.py --no-download   # только пересобрать вёрстку
python _serve.py 8000             # http://127.0.0.1:8000/ — локальный просмотр
```

`_serve.py` в git не попадает (`_*.py`): отдаёт папку проекта, а отсутствующие
кадры `archive/` подтягивает с живой страницы и кэширует в `~/.cache/camufa-local`.

Правила работы:

- правки — в `improve/v2`, затем `git checkout main && git merge --ff-only improve/v2`;
- `git push origin improve/v2 main` — и сайт обновится сам (push в `main` = публикация);
- `previews/`, `archive/`, `_site/` не коммитить (в `.gitignore`);
- `index.html` — снимок для отката, его пересобирает `refresh.py`; CI всё равно собирает страницу заново;
- `gh` CLI не авторизован, токены не нужны — статус смотреть через публичный API или сайт.

## Мелочи, о которых легко забыть

- GitHub Pages отдаёт HTML с `max-age=600` — до 10 минут может показываться старая версия.
- После смены `Pages → Source` сайт живёт только после первого успешного запуска workflow.
- Откат: `Settings → Pages → Source → Deploy from a branch → main / root`
  (старый `index.html` специально оставлен в репозитории).
- Смена расписания в GitHub вступает в силу не мгновенно.
- Добавление камеры: строка в `cams.json` вида
  `{ "id": "1543379809PFL793", "jk": "ЖК Новая Дема", "title": "Камера 7" }`.
